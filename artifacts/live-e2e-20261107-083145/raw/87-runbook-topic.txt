WHEN TO USE  RKE2 certificates (API server, kubelet, supervisor, etcd) are close to expiry - see key C / kdash --certs
  ! RKE2 renews certificates with under 120 days left only when the service starts; a node that never restarts expires silently.
  ! This renews leaf certificates. It does not rotate the CA (that is rke2 certificate rotate-ca - a separate, planned procedure).

  STEP 1  check, on each server
      read   [on dev] sudo rke2 certificate check --output table

  STEP 2  rotate on ONE server at a time
      CHANGE [on dev] sudo systemctl stop rke2-server
      CHANGE [on dev] sudo rke2 certificate rotate  # add --service NAME to rotate only some (e.g. --service api-server)
      CHANGE [on dev] sudo systemctl start rke2-server
      read   kubectl --context vcluster-docker_dev get nodes  # the server is Ready again before you continue

  STEP 3  agents
      CHANGE [on each agent] sudo systemctl restart rke2-agent  # renews the agent's certificates (under 120 days left)

  STEP 4  verify
      read   kdash --certs  # nothing left in WARNING / CRITICAL
      note   kubeconfig files that embed a client certificate (e.g. rke2.yaml) may need to be copied again after a rotation
