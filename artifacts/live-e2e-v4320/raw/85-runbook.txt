WHEN TO USE  etcd data is lost or corrupted, or the cluster must go back to a known state
  ! A restore rolls the WHOLE cluster back to the snapshot time: everything created or changed after it is lost.
  ! Restoring onto NEW hosts needs the ORIGINAL server token (it decrypts the bootstrap data in the snapshot).
  ! Snapshots contain the cluster CA keys and all Secrets: copy and store them like secrets.

SNAPSHOTS
  unknown (unavailable) - list them on a server: sudo rke2 etcd-snapshot ls

A. RESTORE ONTO THE EXISTING SERVERS  servers: dev

  STEP 0  prepare (nothing changes yet)
      read   [on dev] sudo rke2 etcd-snapshot ls  # confirm the snapshot is on this node
      read   [on dev] sudo cat /var/lib/rancher/rke2/server/token  # save the server token in your secret store first - needed for any restore onto new hosts
      read   kdash --report  # evidence of the current state before you change it

  STEP 1  stop rke2-server on every server
      CHANGE [on dev] sudo systemctl stop rke2-server  # all servers must be down before the reset

  STEP 2  reset the cluster from the snapshot (on dev only)
      CHANGE [on dev] sudo rke2 server --cluster-reset --cluster-reset-restore-path=/var/lib/rancher/rke2/server/db/snapshots/<SNAPSHOT-NAME>  # wait for: Managed etcd c›
      note   if config.yaml has etcd-s3 settings and you restore this LOCAL file, add --etcd-s3=false

  STEP 3  start rke2-server on dev
      CHANGE [on dev] sudo systemctl start rke2-server  # the reset flag file is removed on this normal start
      read   kubectl --context vcluster-docker_dev get nodes -o wide  # wait until dev is Ready

  STEP 4  on every OTHER server: back up and delete the old etcd data
      CHANGE [on the other servers (none found)] sudo mv /var/lib/rancher/rke2/server/db /var/lib/rancher/rke2/server/db.bak-$(date +%Y%m%d%H%M%S)  # RKE2 asks to back u›

  STEP 5  start rke2-server on the other servers, one at a time
      CHANGE [on the other servers (none found)] sudo systemctl start rke2-server  # they rejoin the restored cluster; wait for Ready before the next

  STEP 6  verify
      read   kubectl --context vcluster-docker_dev get nodes -o wide  # all servers and agents Ready
      read   kubectl --context vcluster-docker_dev get pods -A --field-selector=status.phase!=Running,status.phase!=Succeeded  # what has not come back yet
      read   kdash --doctor && kdash --certs  # API, access and certificates
