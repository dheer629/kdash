# kdash 4.39.0 feature validation

The release was exercised against the Kubernetes cluster in local Ubuntu WSL.
The `kdash-e2e` namespace supplies running and failing workloads, services,
PVCs, certificate fixtures and container logs. The validation runner uses an
isolated kubeconfig, kdash configuration, audit directory and tmux socket.

The run records 200 baseline checks plus 124 extension checks (324 live checks),
31 Secrets-map checks, 33 browser checks and all 20 fixture suites. It saved 136
terminal screenshots (131 run captures plus 5 Secrets-map captures), each with a
native xterm grab and an ANSI replay. The whole-log check read a real
kubelet-rotated file, and the narrow audit table check rendered live events with
wrapped details after masking the operator and host names.

## 4.39.0 terminal and runtime changes

| Change | Validation evidence |
|---|---|
| Pinned table headers | `extended-sticky-pod-header` checks the column header and its colour after scrolling to the last pod rows. |
| Paged help and command palette | `extended-dashboard-help-pagination` verifies colour, advance, back and exit on a 24-row terminal. `extended-command-palette-colour` checks the palette's header and command colours. |
| Structured pod detail | `extended-inspector-summary-style` checks resource columns and status colours. The terminal gallery records Describe, Events and Why panes. |
| Log styling and empty states | `extended-inspector-log-colour` checks warning and informational colours. `extended-inspector-empty-pane-export` checks that the empty ERROR filter's guidance stays out of the saved data. |
| I/O source discovery | `view-io` records measured rates from two kubelet cAdvisor samples. |
| Audit verification | `audit-verify` checks the live hash chain. `tests/test-runtime.sh` checks that a failed hash worker returns an error. |
| Audit table layout | `extended-audit-terminal-wrapped-details` renders live events in a 100-column, 30-row window with wrapped DETAIL cells, masked identities and the framed footer. |

## Coverage limits

The local cluster has one node. The run exercises placement and resource
accounting using that inventory. Volume usage depends on the provisioner's
metrics. The local cluster uses certificate authentication, and OIDC validation
uses controlled helpers.

Published text replaces the local operator identity with
`operator@validation-host`; the run's `REDACTION.md` lists the substitutions. The
hash-chained audit log is untouched and `audit-verify.txt` records that it still
verifies. The isolated test configuration is not published, and the browser
checks were re-run against the redacted reports.
